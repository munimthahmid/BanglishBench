# Banglish Human Review Workflow for v5

Updated: 2026-05-28

## Purpose

The current validation-200 v4 Banglish fields are still rule-based. Before a
final thesis-grade benchmark release, the highest-priority Banglish artifacts
should be manually reviewed and then applied with an auditable script.

## Inputs

- Main review CSV:
  `data/slices/validation_200_v5_review_queue.csv`
- Read-only review packets:
  `reports/validation200_v5_review_packets/README.md`
- Review effort summary:
  `reports/validation200_v5_review_effort_summary.md`
- Earlier 54-row priority packet:
  `reports/banglish_human_review_packet_v2.md`
- Heuristic suggestion packet:
  `reports/banglish_review_suggestions_v3.md`
- Auto-suggested candidate report:
  `reports/validation200_v4_auto_suggested_diff.md`
- Operator checklist:
  `reports/validation200_v5_human_review_operator_checklist.md`
- Pre-freeze validator:
  `scripts/validate_banglish_review_queue.py`
- Application script:
  `scripts/apply_banglish_review.py`

The main review CSV already has these fields:

- `reviewed_banglish`
- `quality_label`
- `review_notes`

The older suggestion CSV
`data/slices/banglish_human_review_priority_v3_suggestions.csv` adds:

- `suggested_banglish`
- `suggestion_notes`

These fields are only review aids. They are not human-reviewed labels and should
not be copied blindly into `reviewed_banglish`.

An additional auto-suggested candidate slice exists:

- `data/slices/validation_200_v4_auto_suggested.jsonl`
- `data/slices/validation_200_v4_auto_suggested.manifest.json`
- `results/analysis/validation200_v4_auto_suggested_audit.csv`
- `reports/validation200_v4_auto_suggested_diff.md`

It was generated by:

```bash
python3 scripts/apply_banglish_auto_suggestions.py \
  --input data/slices/validation_200_v4.jsonl \
  --output data/slices/validation_200_v4_auto_suggested.jsonl \
  --audit-output results/analysis/validation200_v4_auto_suggested_audit.csv \
  --report-output reports/validation200_v4_auto_suggested_diff.md
```

This candidate is useful for reviewer triage or sensitivity runs, but it is not
v5 and must not be described as human-reviewed.

The broader current review queue derived from this candidate is:

- `data/slices/banglish_auto_suggested_review_priority_v1.csv`
- `reports/banglish_auto_suggested_review_priority_v1.md`
- `data/slices/validation_200_v5_review_queue.csv`
- `reports/validation200_v5_review_queue.md`
- `reports/validation200_v5_review_packets/README.md`

This queue includes blank `reviewed_banglish`, `quality_label`, and
`review_notes` fields. It prioritizes the auto-suggested edits by edit count and
whether the current Qwen2.5/Qwen3 v4 runs still miss the item. The
`validation_200_v5_review_queue.csv` version also includes Bangla and English
source text for reviewer context.

Allowed quality labels:

- `ok`: current Banglish is acceptable.
- `minor_edit`: mostly acceptable, with a small reviewed replacement.
- `major_edit`: current Banglish needs substantial replacement.
- `bad`: item should not be trusted for a human-reviewed clean Banglish subset.

## How To Freeze Validation-200 v5

After filling the review CSV, first validate it:

```bash
python3 scripts/validate_banglish_review_queue.py --require-complete
```

This writes:

- `reports/validation200_v5_review_validation.md`
- `results/analysis/validation200_v5_review_validation_issues.csv`

Only freeze when the validator has zero errors and zero pending rows. Then run:

```bash
python3 scripts/apply_banglish_review.py \
  --input data/slices/validation_200_v4.jsonl \
  --review data/slices/validation_200_v5_review_queue.csv \
  --output data/slices/validation_200_v5.jsonl \
  --audit-output results/analysis/validation200_v5_banglish_review_audit.csv \
  --quality-status human_reviewed_banglish_v5
```

Expected side outputs:

- `data/slices/validation_200_v5.manifest.json`
- `results/analysis/validation200_v5_banglish_review_audit.csv`

## Script Behavior

- If `quality_label` is `minor_edit` or `major_edit`, `reviewed_banglish`
  must be non-empty and replaces `banglish_clean`.
- If `quality_label` is `ok` and `reviewed_banglish` is empty, the current
  Banglish is accepted and `quality_status` is updated.
- If `quality_label` is `bad`, the item is marked as bad and must not include a
  replacement.
- If review fields are blank, the item is left unchanged.
- Invalid label/replacement combinations raise an error before writing output.
- `banglish_noisy` is not regenerated by this script.
- Item ids and item order are preserved.
- The validator blocks dangerous combinations before freezing, including
  `bad` rows with replacement text, edit labels without replacement text,
  changed digit sequences, changed option labels, and changed answer-format
  instructions.

## After Freezing

Run the audit tools:

```bash
python3 scripts/audit_banglish_artifacts.py \
  data/slices/validation_200_v5.jsonl \
  --summary-output results/analysis/validation200_v5_banglish_artifact_summary.csv \
  --examples-output results/analysis/validation200_v5_banglish_artifact_examples.csv
```

Then rerun only the clean Banglish condition for the main models if the v5
review changed enough items to matter. Do not rerun full Bangla and English
baselines unless item ids or prompts outside Banglish changed.

## Thesis Use

The v5 slice should be described as human-reviewed for prioritized artifact
classes, not necessarily as fully natural human Banglish. If only the 54
priority items are reviewed, state that exact coverage.
